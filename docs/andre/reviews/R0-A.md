# R0 review A (tasks A1-A8): signing, certification, encryption, stamp, library, initials, contract and pack flows

Reviewed commit `0ac8a12` (worktree `/home/andre/projects/andre-pdf-review`, Debug core build `build-review`).
Scope: `pdfdocumentsigner.{h,cpp}`, `pdfsignaturestamp.{h,cpp}`, `pdfsignaturelibrary.{h,cpp}`, `pdfpageinitials.{h,cpp}`,
`pdfsignaturelinefinder.{h,cpp}`, `pdfcontractpack.{h,cpp}`, `pdfcertificatemanager.cpp` (`createEntryFromPkcs12`),
the `PDFPageContentStreamBuilder::end` fix, and `Pdf4QtEditorPlugins/SignaturePlugin/*` (read only, not built here).

Method: read the diff against upstream `905cefa`, ran the existing suite (`UnitTestsSignatureBuilder`: 63 passed),
then added ten temporary probe tests to the worktree (removed again) to prove or disprove the suspicions below.
"Proven" = a probe failed or printed the behaviour; "plausible" = by reading only.

## Summary

The certification (DocMDP) and encrypt-then-certify implementation is structurally correct: `/Reference`, `/Perms`,
P values, permission bits, the unencrypted `/Contents`, the random owner password and the post-write verification
all check out, and tampering inside the signed range is detected. The serious problems are around the flows the
fork builds on top of it:

1. **High.** Any attempt to sign a PDF that is *already* encrypted - including a file Andre PDF itself produced with
   "encrypt before signing" and certified P=2 so "the other party can still sign" - throws an unhandled
   `std::bad_function_call` from `PDFDocumentSigner::sign` (the editor dies), and the fallback path fails verification.
   Andre PDF therefore cannot countersign its own encrypted contracts, nor sign any third-party encrypted PDF.
2. **Medium.** Signature lines on pages with `/Rotate` are detected as a 0.8 pt sliver, so the signature image placed
   on them is invisible while the document is still certified and reported as signed.
3. **Medium.** The line finder flags the SA attestation clause ("Signed at ___ on this ___ day of ___") as signature
   lines and silently drops "Signature & Date: ___" and "For the Purchaser: ___"; the "every line decided" rule only
   covers lines the finder sees.
4. **Medium.** The pack batch flow defaults to "Sign every signature line" and locks with P=1, with no per-line review.
5. **Medium.** The QR "File before signing SHA-256" cannot be checked by anyone when the file was encrypted (whole
   rewrite), which is the flow the stamp was built for.

Everything else is low or cosmetic. Memory safety, DPAPI use, file writes and the user-text paths into PDF objects
are sound.

## Verified as correct

- DocMDP: signature dictionary gets `/Reference [<< /Type /SigRef /TransformMethod /DocMDP /TransformParams << /Type /TransformParams /P n /V /1.2 >> >>]`, catalog `/Perms /DocMDP` references the signature dictionary; `mergeTo` is recursive so an existing `/Perms` entry survives; certification refused when the document already has a signed field or document timestamp, or for a `DocTimeStamp`; P 1/2/3 round-trip through `getCertificationPermissions`; an approval signature after a P=2 certification keeps the certification (existing test).
- Encrypt-then-certify: AES-256 (R6); owner password 32 letters from `QRandomGenerator::system()` (CSPRNG, ~150 bits) and discarded; permission word base `0xFFFFF0C0` has bits 1-2 clear and 7-8, 13-32 set, `Permission` enum bit numbering matches ISO 32000-2 Table 22; printing/copy/accessibility always, bit 9 for P=2, bits 6+9 for P=3, none for P=1; the writer leaves signature `/Contents` unencrypted (`PDFDecryptOrEncryptObjectVisitor::visitDictionary`), everything else including the visible appearance stream is encrypted and decrypts correctly (probe: `/AP /N` decodes, contains `Do`, one image XObject); the written file is verified with the new password; a wrong password is refused; encryption of an already-signed document is refused.
- Incremental updates: approval signature over an (unencrypted) certified document keeps both signatures valid; ByteRange/placeholder logic is upstream's and unchanged; placeholder uniqueness is enforced; tampering inside the signed range is detected (`encryptedCertification` test).
- `hasExistingSignatures` counts only fields with non-empty `/Contents`, including document timestamps.
- `PDFPageContentStreamBuilder::end` fix: depth-limited walk to inherited `/Resources`, only a dictionary is merged, new content keeps its own resources when the page tree has none; covered by `initialsOnEveryPage`.
- Initials: display-to-page transform for all four rotations matches `/Rotate` (tested by rendering), crop box honoured, skipped pages, `PlaceAfter` appends a new content stream reference (shared content streams are not modified in place).
- Contract checklist: Sign & Lock disabled until every line is decided and at least one is "I sign" and the library has a signature; the plugin re-checks `isComplete()`; "Other party" lines switch the proposal to P=2.
- Signature library: `QSaveFile` atomic save, owner-only permissions, `CryptProtectData` user scope with `CRYPTPROTECT_UI_FORBIDDEN`, `SecureZeroMemory` + `LocalFree` on the decrypted buffer, magic/version/count checks; hostile lengths rejected in 0 ms (probe); `extractSignature` alpha stays in 0..255, crop is intersected with the image, null/empty/no-ink inputs handled, very large scans downscaled.
- `createEntryFromPkcs12`: frees `PKCS12`, `X509`, `EVP_PKEY`; empty password passed as NULL; wrong password returns `nullopt` (mobile test).
- Contract pack: range parser validates bounds, order and overlap; `fromStartPages` sorts, dedupes and clamps; `suggestFromOutline` tolerates missing actions/named destinations; `assemble` catches its own exceptions; output files are never overwritten (suffix loop); file names strip separators, reserved characters and controls.
- User text (reason, contact info, slot names, bookmark titles) reaches PDF objects only through the object writer or QDataStream - no injection path found.
